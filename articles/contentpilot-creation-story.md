## はじめに

「投資した分を回収するには、売るものと売れる仕組みの両方が必要だ」

今年の初めに投資回収計画を立てた。月6万円以上の収益を出さないといけない。Claude Codeを使えばプロダクトは作れる。でも、認知から販売までのマーケティング活動をコントロールすることの方がはるかに難しかった。

だから自分のために作った。ContentPilot ― Zenn、note、Xのメトリクスを一元管理し、認知→流入→エンゲージメント→収益化のファネルで分析するツールだ。

## なぜMCPを採用したのか

### API課金のジレンマ

分析にはLLMの力が必要だった。しかし既にClaudeのMaxプラン（月額課金）に入っている。ここにさらにAPI課金を重ねると、月6万円の収益目標に対して出費が嵩む。これは矛盾する。

そこで目をつけたのが **MCP（Model Context Protocol）** だ。MCPサーバーをローカルに立てれば、Claude Code（Maxプラン内）から直接分析できる。追加のAPI課金はゼロ。

### でも、そこで生まれたジレンマ

> Claude Codeだけで分析が完結してしまうのでは？
> アプリの立ち位置は単なるデータの可視化なのでは？

これは今でも完全に答えが出ていない。MCPツールで `analyze_profile` を呼べば構造化レポートが返ってきて、Claude Maxが改善提案をしてくれる。アプリがなくても分析はできてしまう。

現時点での暫定解は：
- **アプリ = データの蓄積・可視化・トレンド追跡**（日次でcronが自動収集）
- **Claude Code = リアルタイム分析・提案・実行支援**

両者は補完関係にある。アプリがデータを溜め、LLMがそれを解釈する。

## 技術スタック

```
フロントエンド: Next.js 15 (App Router) + Tailwind CSS
バックエンド:   Supabase (PostgreSQL + Auth + Edge Functions + pg_cron)
分析:          MCP Server (TypeScript) → Claude Code経由
デプロイ:       Vercel
```

**ポイント:** API課金なしで動く。Supabaseの無料枠 + Vercelの無料枠 + Claude Maxプラン（既存課金）のみ。

## 非エンジニアがAIで開発して驚いたこと

正直に言う。**誰でもアプリケーションやDBの設計ができるようになってしまった。**

動くものを作ること自体は、もはや障壁ではない。使い込んでいくと多少の修正は必要だが、今まで考えられなかったものが形になる。

だからこそ、**「何を作るのか？」「何を解決したいのか？」** という本質的な問いかけの方が重要で難しい。技術的なHowよりもWhyが問われる時代になった。

## Claude Codeとの協働開発

ものすごいスピードで画面上に動く仕組みが出来上がっていく。これには純粋に興奮した。

ただし、**使い勝手やデザイン性は自分で操作してみて気づくことの方が多い。** AIが作ったUIを実際に触ってみると「ここは使いにくい」「この情報はこう並べた方が直感的」という発見がある。この体験のフィードバックループは、まだ人間の手が必要だ。

## これからのContentPilot

ただの分析ツールで終わらせるつもりはない。

目指すのは **認知から収益化までを実行支援するツール** だ。「どうすればより多くの認知を得られるか？」を分析し、「それに対してどう対応すべきか？」を提案し、できればその実行までサポートする。

そして、自分のためだけでなく、**他のクリエイターにも展開できる仕組み** にしたい。

## まとめ

- MCPの採用でAPI課金ゼロの分析基盤を構築した
- 非エンジニアでも動くものは作れる。問題は「何を作るか」
- アプリとLLMは補完関係。データを溜めるアプリ × 解釈するLLM
- 分析で止まらず、収益化まで繋がるツールを目指す

思いついたら作る。考えているだけで止まらない。その精神で、これからも作り続ける。
